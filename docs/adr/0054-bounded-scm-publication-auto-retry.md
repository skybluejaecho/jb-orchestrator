# ADR 0054: 재시도 가능한 SCM 게시를 제한된 backoff로 다시 실행한다

## 배경

ORCH-056은 일시적인 공급자 장애와 영구 실패를 구분하지만 모든 복구는 여전히 운영자의 수동
요청을 필요로 한다. 짧은 GitHub 장애나 네트워크 단절마다 사람이 개입하면 작업이 불필요하게
멈춘다. 반대로 무제한 즉시 재시도는 외부 API를 과도하게 호출하고 잘못된 정책을 숨길 수 있다.

## 결정

- 자동 재시도는 SCM Worker의 명시적 옵션이며 기본 한도는 0으로 비활성화한다.
- `failure_retryable=true`인 실패만 예약할 수 있다.
- `automatic_retry_limit`은 최초 시도 이후 허용할 자동 재시도 횟수다.
- 코어, CLI와 데이터베이스가 한도를 0에서 10 사이로 제한하여 사실상 무제한 설정을 막는다.
- 실패 원장에 한도와 `next_attempt_at`을 저장하여 Worker 재시작 후에도 일정을 유지한다.
- 지연은 최초 실패부터 `base_delay * 2^n`으로 증가하며 설정된 최대 지연을 넘지 않는다.
- 예약 시간이 되기 전에는 어떤 Worker도 레코드를 claim할 수 없다.
- 시간이 되면 동일한 게시 ID를 다시 claim하고 `attempt_count`를 증가시킨다.
- 한도가 소진되거나 실패가 재시도 불가이면 terminal failed 상태로 남긴다.
- 예약 시 `scm_publication.retry_scheduled` 이벤트를 실패 이벤트 다음에 기록한다.
- 명시적 수동 재시도는 예약을 취소하고 즉시 pending으로 전환한다.

## 결과

일시적인 공급자 장애는 원장과 시도 이력을 유지한 채 자동 복구할 수 있다. 기본 설정에서는
ORCH-055의 수동 제어 동작이 그대로 유지된다. Jarvis는 저장된 다음 시도 시각과 한도를 표시하며
브라우저가 자체 타이머로 게시를 다시 요청하지 않는다.

시도별 상세 원장, 자동 재시도 취소 전용 명령, 정책의 프로젝트별 설정은 후속 변경으로 분리한다.
