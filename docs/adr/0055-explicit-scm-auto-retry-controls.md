# ADR 0055: 예약된 SCM 자동 재시도는 명시적으로 취소하거나 즉시 실행한다

## 배경

ORCH-057은 재시도 가능한 게시 실패를 제한된 backoff로 예약한다. 그러나 운영자가 장애 원인을
확인해 더 이상 호출하지 않으려 하거나, 공급자가 복구되어 예약 시각보다 먼저 다시 실행하려는
경우 제어 수단이 없다. 브라우저가 로컬 상태만 바꾸면 다른 Jarvis 화면과 Worker가 서로 다른
판단을 하게 된다.

## 결정

- `POST /v1/scm-publications/{id}/automatic-retry/cancel`은 실패 원장의 예약을 제거한다.
- 취소는 `next_attempt_at`을 비우고 자동 재시도 한도를 0으로 만들지만 상태, 실패 분류, 사람이
  읽는 실패 이유와 누적 시도 횟수는 보존한다.
- 이미 예약이 없는 실패에 대한 반복 취소는 같은 레코드를 반환하고 새 이벤트를 만들지 않는다.
- 성공한 게시 또는 pending/claimed 게시에는 취소할 예약이 없으므로 충돌로 처리한다.
- row lock을 사용하여 Worker claim과 취소가 동시에 발생해도 하나만 먼저 확정되게 한다.
- 취소 성공은 수행 계정을 포함한 `scm_publication.automatic_retry_cancelled` 이벤트로 기록한다.
- 예약된 실패에 기존 명시적 retry API를 호출하면 예약을 제거하고 즉시 pending으로 전환한다.
- 두 명령 모두 publication에서 project를 해석하고 기존 `scm.publish` 권한으로 제한한다.
- Jarvis는 예약된 항목에 `예약 취소`와 `지금 재시도`를 함께 제공한다.

## 결과

자동 복구는 운영자를 잠그지 않는 선택적 정책으로 유지된다. 취소 후에도 실패 증거가 보존되며,
즉시 재시도는 ORCH-055의 기존 원장 보존 규칙을 그대로 사용한다. Jarvis는 Control Plane을 통해
명령하고 SSE 이벤트로 다른 화면과 상태를 맞춘다.
