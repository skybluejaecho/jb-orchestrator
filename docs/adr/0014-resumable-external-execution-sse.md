# ADR 0014: 외부 실행 SSE는 단조 증가 이벤트 순번으로 재개한다

## 상태

승인됨

## 배경

Jarvis 같은 GUI는 폴링 외에도 외부 실행 상태 변경을 빠르게 받아야 한다. SSE 연결은
네트워크, 프록시, 서버 재시작으로 끊길 수 있으므로 연결 중에만 존재하는 메모리 메시지는
정합성의 기준이 될 수 없다. 기존 이벤트 UUID와 발생 시각만으로는 같은 시각에 기록된
여러 이벤트의 인과 순서도 보장할 수 없다.

## 결정

- `events.sequence`를 데이터베이스가 발급하는 단조 증가 기본 키로 사용한다.
- 이벤트 UUID는 외부에 노출하는 안정적인 식별자이자 SSE `id`로 유지한다.
- 서버는 UUID 커서가 가리키는 순번보다 큰 외부 실행 이벤트를 순번대로 조회한다.
- `GET /v1/external-executions/events/stream`은 저장된 이벤트를 먼저 재생한 다음 원장을
  폴링한다.
- 재연결 시 표준 `Last-Event-ID` 헤더를 사용하며, 최초 연결은 `after` 쿼리 매개변수도
  지원한다.
- 유휴 연결에는 주기적으로 SSE 주석 하트비트를 전송하고 프록시 버퍼링을 비활성화한다.

## 클라이언트 흐름

```text
Jarvis ── GET SSE ──> API ── 커서 이후 조회 ──> PostgreSQL events
   ^                    │
   └── id + event + data┘

연결 끊김 ── Last-Event-ID ──> 누락 구간 재생 ──> 실시간 tail 재개
```

브라우저 `EventSource`는 재연결 시 마지막으로 받은 이벤트 ID를 자동으로 전송한다. 저장해
둔 커서로 새 화면을 시작할 때는 `?after=<event-id>`를 사용한다.

## 결과

SSE는 PostgreSQL 원장과 같은 사실을 전달하며 일시적인 연결 단절로 이벤트를 잃지 않는다.
현재 구현은 연결마다 짧은 DB 폴링을 수행한다. 연결 수가 크게 증가하면 공개 계약은 유지한
채 PostgreSQL `LISTEN/NOTIFY` 또는 전용 메시지 브로커를 깨우기 신호로 추가할 수 있다.
API 인증과 프로젝트 단위 접근 제어는 별도 보안 작업에서 다룬다.
